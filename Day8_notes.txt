-WHY USE PYTHON IN ROBOTICS SOFTWARE
    ROS2's primary client library, rclpy, is pure Python
    
    Massive amount of libraries
        *PYP package manager is super helpful for downloading these libraries

    Problem: We must write in C when interfacing with hardware. Python is too abstracted

-SOME THINGS ABOUT PYTHON
    No void setup(), no main(), no semicolons, no braces

    It is just simple, plain, text

    What's missing? ---> There is no compile step
        *Errors appear at runtime. No way to catch bugs early.

    Unit testing ---> Snippets of code to check to see if a part is running


-CHECKING TYPES

-LISTS - DYNAMIC ARRAYS
    You can append arrays in python (using append() - adds value at the end of a list)

    indexing can be done both ways
        index[1] - second item
        index[0] - first item
        index[-1] - last item

    You can slice up lists into smaller sublists
        index[a:b] - item at index a,b
        index[:b] - first two items
        sensors[::a] - reverse order

-TUPLES - IMMUTABLE LISTS
    Good for functions returning known data types and multiple values
        *Keeps us from getting confuse

    Not changeable


-DICTIONARIES
    You can create pairs of data as a list
        * "Name":value ----> This is an example of a piece of data
        * dictionary['newItem'] = newValue ---> adds new key to the end of the dictionary
        * you can look things up by name, but you can't index
    
    Iterating through all values can be done by key and values


-WHY THIS MATTERS FOR ROS2
    ROS2 Messages often feel like nexted dictionaries when inspected

    Parameters are commonly loaded as dictionaries
